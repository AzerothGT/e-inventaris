1

Project setup & design

Foundation, ERD, UI wireframes

Wk 1–2 ▼
  • Init repo: Next.js 14 (App Router) + TanStack Query + TanStack Table
  • Set up SQLite via Turso (libsql) — free tier sufficient for school scale
  • Design ERD: barang, lokasi, lemari, permintaan, approval_log, users
  • Define role enum: penjaga_lab | orang_tu | kaprog | wakasek_kurikulum | wakasek_kesiswaan | kepala_sekolah | tu_admin
  • Wireframe 5 key screens: Dashboard, Form Permintaan, Approval Queue, Inventaris, Terima Barang
  • Set up auth: NextAuth.js with credential provider + role-based middleware

Key output

Running skeleton app + DB schema migration files

Risk

SQLite concurrency on Vercel — use Turso to avoid serverless limits

2

Inventory module

CRUD barang, lokasi, kondisi

Wk 3–4 ▼
  • API routes: GET/POST/PATCH /api/barang, /api/lokasi, /api/lemari
  • TanStack Query hooks for all data fetching + optimistic updates
  • TanStack Table for inventory list — sortable, filterable by lokasi/kondisi/merk
  • Form input barang: Nama, Merk, Kuantitas, Lokasi Ruangan, Lemari, Kondisi (Baik | Rusak)
  • Status badge logic: Baik/Hidup Rusak
  • Export view (CSV) for inventory report
3

Pengadaan & approval flow

Permintaan → approval chain → notif

Wk 5–7 ▼
  • Form Permintaan Barang (Penjaga Lab / Orang TU): nama barang, jumlah, alasan, prioritas
  • Approval state machine: draft → pending_kaprog → pending_wakasek_kur → pending_wakasek_kes → pending_kepsek → approved | rejected
  • Each approver sees their own queue with Acc / Tolak + catatan
  • Approval log table: siapa, kapan, status, catatan — full audit trail
  • Notification system: in-app badge + optional email (Resend.com free tier) when status changes
  • TU Admin receives notif on final approval → trigger "proses pembelian"

State machine tip

Store current_step as enum in permintaan table. Each role only sees requests where current_step = their_step. Simpler than a separate workflow engine.

4

Terima barang & masuk inventory

TU menerima → otomatis update DB

Wk 8 ▼
  • TU konfirmasi barang diterima: input kuantitas aktual, kondisi, lokasi, lemari
  • On confirm → permintaan.status = received + insert baris baru di tabel barang (atau increment qty jika barang sudah ada)
  • Auto-set kondisi default Baik; TU bisa override ke Rusak
  • Generate nomor inventaris otomatis (prefix + year + sequence)
  • Notif ke pemohon: "Barang [X] sudah diterima dan masuk inventaris"
5

Dashboard & laporan

Ringkasan per role, statistik

Wk 9 ▼
  • Dashboard per-role: Penjaga Lab lihat status permintaannya; Kepala Sekolah lihat semua pending
  • Metric cards: total barang, barang rusak, permintaan pending, permintaan bulan ini
  • TanStack Table dengan filter kondisi + lokasi + tanggal
  • Laporan PDF/CSV: daftar inventaris per ruangan, riwayat pengadaan
6

Testing & deployment

QA, staging, go-live

Wk 10–12 ▼
  • UAT dengan 1 user per role — jalankan skenario end-to-end
  • Vercel preview deployment untuk review sebelum production
  • Set up Vercel environment vars: DATABASE_URL (Turso), NEXTAUTH_SECRET, RESEND_API_KEY
  • Seed database: lokasi ruangan, lemari, akun awal tiap role
  • Training singkat 30 menit per kelompok pengguna
  • Soft launch + monitor error via Vercel logs

Catatan SQLite + Vercel

Vercel serverless functions tidak bisa menulis ke SQLite file lokal karena filesystem-nya read-only. Gunakan Turso (remote SQLite via libsql) — gratis, latency rendah, dan Drizzle sudah punya adapter resmi.
